# خارطة طريق Malek Finance — مالك فاينانس

> الفرع النشط الوحيد: `feature/voice-finance`. لا تعدّل `main`.
>
> الحالة هنا تفرق بين **تنفيذ الكود** و**اعتماد الميزة**. وجود الاختبار في المستودع لا يعني أنه نجح؛ ولا تُعتبر الميزة معتمدة حتى ينجح CI وتُجرّب على جهاز مناسب.

## المرحلة 1 — الأساس والهوية
**الحالة: منفذة برمجياً؛ التحقق النهائي مستمر.**
- [x] Kotlin وJetpack Compose وMaterial 3، واجهة عربية RTL وهوية داكنة بنفسجية.
- [x] تنقل رئيسي إلى الرئيسية والعمليات والصوت والتقارير ومالي.
- [x] Room كقاعدة محلية، عمل دون اتصال للوظائف المالية الأساسية.
- [x] دعم Android API 23+ والعملات YER وUSD وSAR وAED مع فصل الأرصدة.
- [ ] مراجعة نهائية لتكبير الخط وإمكانية الوصول وقارئ الشاشة على أجهزة فعلية.

## المرحلة 2 — سلامة دفتر الأستاذ وقاعدة البيانات
**الحالة: تغييرات واختبارات مضافة؛ اعتماد CI/المحاكي ما زال مطلوباً.**
- [x] حسابات BigInteger وتخزين المبالغ بوحدات minor لمنع أخطاء التقريب والفيض.
- [x] تغطية أنواع INCOME وEXPENSE وDEBT_ISSUED وDEBT_RECEIVED وSAVINGS_CONTRIBUTION وSAVINGS_WITHDRAWAL.
- [x] رفض السجلات ذات المبالغ غير الموجبة والتحويلات غير الصالحة في احتساب الرصيد.
- [x] خدمة تحويل ذرية تتحقق من المحفظتين والعملة والرصيد داخل Room transaction واحدة.
- [x] اختبارات للتحويل الوارد والصادر، السحب الزائد، العملة المختلفة، المحفظة نفسها، والتنافس على الرصيد.
- [x] اختبارات rollback عند فشل خطوة لاحقة، واختبارات قيود منع تكرار استحقاقات الرواتب والمصروفات والفواتير والديون والادخار.
- [x] توحيد قائمة migrations 1→12 بين التطبيق وعامل التذكير.
- [x] اختبار Instrumentation يبني قاعدة v1 قديمة ثم يطلب من Room ترقيتها حتى v12 ويتحقق من بقاء السجل والجداول.
- [ ] نجاح تشغيل اختبارات Room على محاكي Android والتحقق من Room schema validation.
- [ ] اختبار قواعد v1/v6/v10 فعلية وسيناريوهات rollback والتزامن على أجهزة حقيقية.

## المرحلة 3 — المساعد الصوتي وفهم العربية
**الحالة: منفذة جزئياً مع توسعة كبيرة للاستعلامات.**
- [x] فصل Android SpeechRecognizer عن VoiceTransactionParser النقي.
- [x] دعم الأرقام العربية والفارسية واللاتينية وبعض الأعداد المنطوقة: خمسة آلاف، خمسة وعشرين ألفاً، مئة وخمسين ألفاً وألفين.
- [x] فهم اليوم وأمس وأول أمس، واختيار أفضل نتيجة تعرف عند توفر درجات الثقة.
- [x] مسودة دخل/مصروف قابلة للتعديل، ولا تحفظ إلا بعد تأكيد المستخدم.
- [x] إلغاء المسودة بالصوت أو اللمس، ومنع النقر المتكرر أثناء الحفظ.
- [x] الإدخال اليدوي البديل عند رفض إذن الميكروفون أو غياب خدمة التعرف.
- [x] استعلامات صوتية للرصيد والدخل والمصروف والملخص وآخر العمليات والديون والادخار والميزانيات والفواتير القادمة.
- [x] تصفية استعلامات الدخل والمصروف حسب التصنيف، والاستعلام عن دين شخص محدد عند ذكر اسمه.
- [x] إنشاء مسودة تحويل صوتي؛ اختيار المصدر والوجهة والمبلغ ومراجعتها قبل التأكيد. التنفيذ يمر عبر محرك التحويل الذري.
- [ ] دعم إنشاء الديون ومساهمات الادخار والفواتير صوتياً مع مراجعة وتأكيد مستقلين.
- [ ] قياس دقة فهم اللهجة اليمنية على مجموعة عبارات واقعية وأجهزة متعددة.
- [ ] التحقق من التعرف دون إنترنت فعلياً؛ تفضيل Offline لا يضمن أن مزود النظام يدعمه.

## المرحلة 7 — النسخ الاحتياطي والاستعادة
**الحالة: منفذة برمجياً؛ اختبارات المحاكي/الجهاز مطلوبة.**

- [x] أخذ snapshot متسق داخل Room transaction.
- [x] استعادة ذرية؛ لا تتغير البيانات الحالية إذا فشل فك التشفير أو التحقق أو إدخال أي سجل.
- [x] التحقق من ترويسة الملف وحجمه ومخطط v12 والجداول والأعمدة.
- [x] مسح كلمة المرور من مصفوفة الذاكرة بعد اشتقاق المفتاح، وعدم حفظها داخل التطبيق.
- [x] تعطيل Android Auto Backup غير المشفر للبيانات المالية.
- [ ] اختبار ملفات كبيرة وتجربة نقل النسخة واستعادتها على هاتف آخر.
- [ ] تصميم ترقية مستقبلية لنسخ احتياطية من مخططات أحدث/أقدم دون المخاطرة ببيانات المستخدم.

## قواعد التنفيذ
1. استمر على `feature/voice-finance` فقط؛ لا تعدّل `main`.
2. لا توقف تنفيذ الميزات انتظاراً للبناء؛ أكمل العمل المخطط، ثم اجمع أخطاء CI وأصلحها دفعةً دفعة.
3. لا تضع علامة اعتماد نهائي قبل نجاح الاختبارات ذات الصلة وتجربة الجهاز.
4. لا تخترع نجاحاً أو ملف APK أو توقيعاً غير موجود فعلياً.
5. لا تنفذ أي دفع أو تحويل أو حفظ صوتي دون مراجعة وتأكيد واضح من المستخدم.
