# خارطة طريق Malek Finance — مالك فاينانس

> الفرع النشط الوحيد: `feature/voice-finance`. لا تعدّل `main`.
>
> الحالة تفرق بين **تنفيذ الكود** و**اعتماد الميزة**. وجود الاختبار في المستودع لا يعني أنه نجح؛ ولا تُعتبر الميزة معتمدة حتى ينجح CI وتُجرّب على جهاز مناسب.

## المرحلة 1 — تثبيت الأساس
**الحالة: منفذة برمجياً؛ التحقق النهائي مستمر.**
- [x] Kotlin وJetpack Compose وMaterial 3، واجهة عربية RTL وهوية داكنة بنفسجية.
- [x] التنقل إلى الرئيسية والعمليات والصوت والتقارير ومالي.
- [x] Room كقاعدة محلية والعمل دون اتصال للوظائف المالية الأساسية.
- [x] Android API 23+ والعملات YER وUSD وSAR وAED مع فصل الأرصدة.
- [ ] مراجعة تكبير الخط وإمكانية الوصول وقارئ الشاشة على أجهزة فعلية.

## المرحلة 2 — دفتر الأستاذ وقاعدة البيانات
**الحالة: تغييرات واختبارات مضافة؛ اعتماد CI/المحاكي ما زال مطلوباً.**
- [x] حسابات BigInteger وتخزين المبالغ بوحدات minor لمنع التقريب والفيض.
- [x] تغطية INCOME وEXPENSE وDEBT_ISSUED وDEBT_RECEIVED وSAVINGS_CONTRIBUTION وSAVINGS_WITHDRAWAL.
- [x] رفض المبالغ غير الموجبة والتحويلات غير الصالحة في احتساب الرصيد.
- [x] خدمة تحويل ذرية تتحقق من المحفظتين والعملة والرصيد داخل Room transaction.
- [x] اختبارات التحويل الوارد والصادر والسحب الزائد والعملة المختلفة والمحفظة نفسها والتنافس على الرصيد.
- [x] اختبار خدمة إنشاء الدين الذرية ورفض الإقراض عند عدم كفاية الرصيد.
- [x] اختبارات مساهمة وسحب الادخار وحدود الهدف والتراجع عند فشل إدخال قيد الادخار.
- [x] اختبارات دفع الفواتير ومنع تكرار الدورة والتراجع إذا فشل إدخال سجل الدفع.
- [x] اختبارات rollback عند فشل خطوة لاحقة ومنع تكرار استحقاقات الرواتب والمصروفات والفواتير والديون والادخار.
- [x] توحيد migrations 1→12 بين التطبيق وعامل التذكير.
- [x] اختبار Instrumentation لترقية قاعدة v1 حتى v12 والتحقق من بقاء سجل قديم والجداول.
- [ ] نجاح اختبارات Room على المحاكي والتحقق من Room schema validation.
- [ ] اختبار قواعد v1/v6/v10 فعلية والتزامن على أجهزة حقيقية.

## المرحلة 3 — المساعد الصوتي وفهم العربية
**الحالة: منفذة برمجياً جزئياً.**
- [x] فصل Android SpeechRecognizer عن VoiceTransactionParser النقي.
- [x] دعم الأرقام العربية والفارسية واللاتينية والأعداد المنطوقة والصيغ اليمنية الدارجة مثل خمسة آلاف وخمسمية وثلاثمية.
- [x] فهم اليوم وأمس وأول أمس، واختيار أفضل نتيجة تعرف عند توفر درجات الثقة.
- [x] مسودة دخل/مصروف قابلة للتعديل، ولا تحفظ إلا بعد تأكيد المستخدم.
- [x] إلغاء المسودة بالصوت أو اللمس، وتصحيح مبلغها صوتياً، ومنع النقر المتكرر أثناء الحفظ.
- [x] الإدخال اليدوي البديل عند رفض إذن الميكروفون أو غياب خدمة التعرف.

- [ ] التحقق من التعرف دون إنترنت فعلياً؛ تفضيل Offline لا يضمن دعمه من مزود النظام.

**الحالة: مسودات العمليات الصوتية الأساسية منفذة؛ اختبارات اللهجة والتحقق على الأجهزة ما زالت مطلوبة.**
- [x] استعلامات الرصيد والدخل والمصروف والملخص وآخر العمليات.
- [x] استعلامات الديون والادخار والميزانيات والفواتير القادمة.
- [x] تصفية الدخل/المصروف حسب التصنيف، وتصفية الدين حسب اسم الشخص عند ذكره.
- [x] فهم نطاقات اليوم/أمس/أول أمس والأسبوع/الشهر/السنة الحالية والسابقة.
- [x] مسودة تحويل صوتي مع اختيار المصدر والوجهة والمبلغ وتأكيد صريح عبر محرك التحويل الذري.
- [x] مسودة إنشاء دين/سلفة صوتية مع اختيار الشخص والاتجاه والمبلغ والمحفظة وخيار تسجيل حركة النقد، عبر خدمة ذرية مشتركة.
- [x] مسودة مساهمة أو سحب ادخار صوتية مع اختيار الهدف والتحقق من الرصيد/المتبقي عبر FinanceSavingsOperations.

- [x] مسودة سداد/تحصيل دين صوتية بمبلغ جزئي واختيار سجل الدين، مع تحقق المتبقي والرصيد وتأكيد المستخدم عبر FinanceDebtPaymentOperations.
- [x] تصحيح مبلغ المسودة بأمر صوتي دون إنشاء عملية جديدة أو تجاوز خطوة المراجعة.
- [ ] توسيع فهم اللهجة والعبارات التصحيحية مع اختبارات انحدار.

## قواعد التنفيذ
1. استمر على `feature/voice-finance` فقط؛ لا تعدّل `main`.
2. لا توقف تنفيذ الميزات انتظاراً للبناء؛ أكمل العمل المخطط ثم اجمع أخطاء CI وأصلحها.
3. لا تضع علامة اعتماد نهائي قبل نجاح الاختبارات ذات الصلة وتجربة الجهاز.
4. لا تدّع نجاحاً أو APK أو توقيعاً غير موجود فعلياً.
5. لا تنفذ أي دفع أو تحويل أو حفظ صوتي دون مراجعة وتأكيد واضح من المستخدم.
